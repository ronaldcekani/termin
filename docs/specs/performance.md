# Spec: Performance Budgets, Benchmarks, CI Gates

Budgets are **gates**: a PR that regresses a gated metric beyond tolerance fails CI unless the budget is consciously changed in this file.

Reference machine: Apple M1, 16 GB, macOS 14, arm64 release build. Secondary: Intel x86_64 (informational).

## 1. Size

| Metric | Budget | Stretch |
|---|---|---|
| `termin` binary (arm64, stripped) | ≤ 8.0 MiB | ≤ 5 MiB |
| `Termin.app` zipped (arm64) | ≤ 4.0 MiB | ≤ 3 MiB |
| Embedded resources (metallib + shell scripts + specs + icons + themes) | ≤ 600 KiB | |

Measured by `cargo xtask size` (prints per-crate contribution via `cargo bloat --crates` when available, else symbol size from `nm`). CI tolerance: +2 % per PR.

Techniques (mandatory): dependency allowlist (`architecture.md §7`), objc2 framework features minimal, no fonts bundled, specs compiled to static tables, `panic = "abort"`, LTO fat, `codegen-units = 1`, `strip`. Avoid generic bloat in hot crates: prefer `&dyn` at cold boundaries (config, IPC, persistence), monomorphize only in hot paths (parser, row builder).

## 2. Memory

Measured as **physical footprint** (`footprint -p <pid>` / `task_info(TASK_VM_INFO).phys_footprint`), which is what Activity Monitor shows.

| Scenario | Budget |
|---|---|
| Launch, 1 window, 1 tab, idle, empty scrollback | ≤ 35 MiB (Metal device + layer ~15 MiB of that) |
| Each additional tab (idle, empty) | ≤ +1.0 MiB (excluding the shell process) |
| Each additional visible pane | ≤ +1.5 MiB (render cache + instances) |
| Scrollback: 10 000 lines × 120 cols of typical colored build log | ≤ +2.5 MiB per tab |
| Scrollback: 100 000 lines same content | ≤ +18 MiB per tab |
| 4 windows × 4 workspaces × 4 panes, idle | ≤ 90 MiB |
| After closing everything but 1 tab and 30 s idle | returns to ≤ launch + 5 MiB |

Rules:
- No unbounded caches. Every cache documents its cap (glyph cache via atlas size, shaped runs 4096, text layouts 512, decoded cold chunks 4/tab, history lazily loaded).
- Hot path allocations: steady-state output processing and rendering must perform **zero heap allocations per frame** (verified with a counting global allocator in a test build, `--features alloc-count`).
- Use `Box<[T]>` for fixed-size data, `shrink_to_fit` after bulk operations, recycle rows.
- Release memory on idle (`renderer.release_idle_resources`, drop decoded cold chunks, shrink write queues).

## 3. Latency and throughput

| Metric | Budget |
|---|---|
| Cold start to first frame (bundled app, 1 tab, restore off) | ≤ 120 ms |
| Shell prompt visible (zsh, empty rc) | ≤ 250 ms |
| Keypress → PTY write (main thread time) | ≤ 0.3 ms |
| Echo → frame presented (key-to-photon minus display) | 1 vsync |
| Frame CPU (full redraw, 4K, 2 panes, 300×80 each) | ≤ 2.0 ms |
| Frame CPU (typical incremental: few rows changed) | ≤ 0.3 ms |
| Parser throughput, ASCII-heavy (`cat` large text) | ≥ 400 MB/s parse-only; ≥ 250 MB/s end-to-end with rendering at 60 Hz |
| Parser throughput, SGR-heavy (colored `ls -R`) | ≥ 150 MB/s |
| Idle CPU (no output, cursor blink on) | ≤ 0.1 % average over 60 s; blink off → 0 wakeups/s |
| Workspace switch | ≤ 1 frame |
| Palette open → first results drawn | ≤ 1 frame; fuzzy over 10k items ≤ 3 ms |

## 4. Benchmarks and tools

- `cargo bench -p termin-vt` — criterion: `advance` on corpora `ascii.bin`, `sgr.bin`, `unicode.bin`, `scroll.bin`, `claude-code.bin` (recorded TUI session). Corpora generated by `cargo xtask corpus` (deterministic generators + a few small recorded files ≤ 2 MiB committed).
- `cargo bench -p termin-render` — row build for a full screen.
- `cargo bench -p termin-editor` — autosuggest, completion.
- `cargo xtask throughput` — launches the app with `TERMIN_BENCH=1`, runs `cat corpus` in a tab, reports wall time and frames.
- `cargo xtask mem` — scripted scenarios from §2 via IPC (`termin new`, `split`, `send`), samples `phys_footprint`, prints table and compares with budgets.
- Instruments templates: Time Profiler, Allocations, Metal System Trace — documented in `docs/qa/profiling.md` (Phase 4).
- Typometer-style latency check: manual, documented.

## 5. CI gates

Run on every PR (macOS runner):
1. `cargo fmt --check`, `cargo clippy --workspace -- -D warnings`.
2. `cargo test --workspace`.
3. `cargo xtask size` vs. `budgets.toml` (stored at repo root).
4. `cargo bench` in quick mode for `termin-vt` parse throughput (fail if > 10 % regression vs. main baseline artifact).
5. `cargo xtask mem --quick` (launch + 1 tab + 10k lines) — fail if over budget.

Nightly: fuzzing 30 min (`fuzz_advance`, `fuzz_tokenize`, `fuzz_config_parse`), full mem scenarios, Intel build.

## 6. Coding rules for hot paths

- No `String` formatting (`format!`) in per-cell/per-row/per-byte paths.
- No `HashMap` with SipHash in hot paths — use `FxHashMap` or arrays.
- No locks held across syscalls on the main thread.
- Prefer `u16` for col/row counts, `u32` for indices into per-terminal tables.
- `#[inline]` only after profiling; `#[cold]` on error paths.
- Every `unsafe` block has a `// SAFETY:` comment; `unsafe` allowed only in `termin-platform`, `termin-render`, `termin-text`, `termin-pty` (pre_exec), and audited spots in `termin-vt` (cell buffer tricks) with tests.
